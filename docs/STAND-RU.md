# Directory Auditor — проверка прототипа на стенде

Версия документа: v1, 8 октября 2026 года. Изменения: первая версия.
Сборка: `v0.1.0-rc1` (прототип). Автор проекта: Александр Цветков.

## 1. Что проверяем

Directory Auditor — бесплатный инструмент аудита безопасности службы каталогов:
Active Directory, Samba AD DC (ALD Pro, РЕД АДМ, Альт Домен), FreeIPA. Один файл,
без установки, только чтение. Цель прототипа: администратор запускает файл и за 5 минут
получает отчёт «что увидит нарушитель в вашем каталоге».

Стенд должен ответить на пять вопросов.

1. Запускается ли файл на целевой ОС без установки и дополнительных компонентов.
2. Подключается ли инструмент с правами обычного пользователя домена.
3. Укладывается ли полный цикл «запуск → отчёт» в 5 минут на домене стенда.
4. Остаётся ли каталог нетронутым: ни одной записи, ни одной блокировки.
5. Совпадают ли находки с тем, что известно о слабых местах стенда.
   Ложные срабатывания и пропуски — главный результат проверки.

Что стенд не оценивает: оценку в баллах (0–100) — в прототипе это заглушка.

## 2. Состав поставки и проверка подлинности

| Файл | Назначение |
|---|---|
| `dirauditor-v0.1.0-rc1-<ОС>-<архитектура>.zip` | Архив: исполняемый файл `dirauditor` (`dirauditor.exe`), `README.md`, `LICENSE`, эта инструкция, `manifest.txt` — перечень всего, что делает программа, и список проверок |
| `SHA256SUMS` | Контрольные суммы архивов и исполняемых файлов |
| `sbom.cdx.json` | Состав сборки (CycloneDX) |

Проверьте контрольную сумму до запуска.

```sh
sha256sum --ignore-missing -c SHA256SUMS                       # Linux, macOS
```

```powershell
Get-FileHash .\dirauditor-v0.1.0-rc1-windows-amd64.zip         # Windows; сравните с SHA256SUMS
```

Сборка не подписана сертификатом разработчика. Windows SmartScreen при первом запуске
покажет предупреждение: нажмите **Подробнее** → **Выполнить в любом случае**.

## 3. Требования

| Что | Требование |
|---|---|
| ОС | Windows 10/11, Windows Server 2016 и новее (x64); Linux x86-64 или ARM64 — любой дистрибутив, сборка статическая; macOS на Apple Silicon |
| Сеть | От машины запуска до контроллера домена: 636/tcp (LDAPS, по умолчанию) или 389/tcp (StartTLS); для Kerberos в Windows — 88/tcp; для автоопределения домена — DNS с SRV-записями |
| Учётная запись | Обычный пользователь домена. Для FreeIPA часть разделов каталога читается только с привилегиями администратора (см. сценарии S5, S6). Для проверки `smb.conf` — запуск на самом контроллере Samba |
| Сертификат LDAPS | Если сертификат контроллера не доверенный на машине запуска, отпечаток берётся из `dirauditor doctor` и передаётся через `--pin` |

Права администратора нужны только в сценарии S6 (FreeIPA: разделы, которые FreeIPA
не показывает обычному пользователю). Если в других сценариях обнаружится проверка,
которая без них не работает, — это замечание к инструменту.

## 4. Быстрый старт

**Windows, доменная машина.** Распакуйте архив, запустите `dirauditor.exe` двойным
щелчком. Откроется браузер со страницей на `127.0.0.1`. Шаги: **1 Подключение**
(обнаруженный домен и текущая учётная запись) → **2 Сканирование** (быстрое — около
минуты, полное — несколько минут) → **3 Результаты**. Отчёт и журнал запуска
сохраняются в папку `dirauditor-out` рядом с программой.

**Linux с графической средой.** `unzip`, при необходимости `chmod +x dirauditor`, затем
`./dirauditor` — страница откроется в браузере. Если браузер не открылся, адрес с одноразовым ключом печатается в терминале.

**Сервер без браузера или скрипт.** Страница доступна только с самой машины, поэтому
используйте командную строку:

```sh
./dirauditor doctor --domain corp.example                     # DNS SRV, порты, сертификат, расхождение часов
./dirauditor scan --server dc01.corp.example                  # текущая учётная запись (Kerberos), LDAPS
./dirauditor scan --server dc01.corp.example --user audit@corp.example   # пароль запрашивается один раз
./dirauditor scan --server dc01.corp.example --user audit@corp.example --pin <sha256>   # самоподписанный сертификат
./dirauditor analyse --snapshot dirauditor-out/snapshot-*.json.zst       # повторный анализ без обращения к контроллеру
./dirauditor manifest --queries                               # что делает программа и какие запросы LDAP посылает
```

Пароль вводится с клавиатуры (ввод скрыт) или подаётся первой строкой `stdin` с
`--password-stdin`. В аргументах командной строки, переменных окружения и файлах пароль
не передаётся.

## 5. Сценарии

Выполните сценарии, применимые к стенду. Для каждого запишите: время от запуска до
отчёта, число объектов и запросов (строка `snapshot:` в журнале), что совпало и что
нет с известным состоянием домена.

| № | Платформа | Учётная запись | Как запускать | Что ожидается |
|---|---|---|---|---|
| S1 | Active Directory, доменная машина Windows | Текущая, Kerberos | Двойной щелчок → **Использовать обнаруженный домен** | Домен и контроллер найдены автоматически; отчёт за ≤ 5 минут; проверки `DSA-0001…0025`; раздел объектов нулевого уровня (Tier 0) совпадает с известным списком администраторов |
| S2 | Active Directory, любая машина | Выделенная учётная запись аудита (обычный пользователь) | **Указать домен и учётные данные** или `scan --user` | То же, что S1. Проверки с пометкой «skipped (tier)» — ожидаемы: они требуют запуска на контроллере |
| S3 | Samba AD DC (ALD Pro, РЕД АДМ, Альт Домен), клиент Linux | Обычный пользователь, `--user` | `scan --server dc1.<домен> --domain <домен> --user audit@<домен>` | Определяется диалект `samba`; проверки `DSA-0001…0025` работают; `DSA-0201…0220` — «skipped (tier)», поскольку требуют `smb.conf`. Без сертификата на контроллере подключение идёт по LDAP (389) с шифрованием Kerberos — в отчёте «LDAP, Kerberos-sealed (no TLS)». Для LDAPS с самоподписанным сертификатом добавьте `--pin` (отпечаток из `doctor`) |
| S4 | Samba AD DC, запуск на самом контроллере | Обычный пользователь для LDAP; чтение `smb.conf` | `scan --server <этот DC> --user … --local` (или мастер: строка «Этот компьютер — Samba AD DC» появится сама) | Дополнительно читаются `smb.conf` через `testparm` и версия Samba; работают `DSA-0201…0220`: NetLogon secure channel, NTLMv1, подпись SMB, `ldap server require strong auth`, обновления DNS, RC4, журналирование |
| S5 | FreeIPA (в том числе ALD Pro на FreeIPA) | Обычный пользователь | `scan --server ipa.<домен> --domain <домен> --user audit --tier 1` | Определяется `freeipa`; читаются конфигурация, HBAC, sudo, пользователи, группы, хосты, службы, CA ACL. Разделы, требующие привилегий (политики паролей, параметры realm, делегирование, разрешения, роли), помечены «not collected»; проверки на них — «skipped (not-collected)», не «pass» |
| S6 | FreeIPA | `admin` | `scan --server ipa.<домен> --domain <домен> --user admin --tier 2` | Все 17 запросов выполнены, разделов «not collected» нет (кроме DNS, если он не установлен); проверки `DSA-0101…0123` оценены полностью |
| S7 | Любая | — | `analyse --snapshot …` на снимке из S1–S6 | Тот же отчёт без единого обращения к контроллеру (проверьте по журналу контроллера или сетевому монитору) |
| S8 | Любая, с намеренно неверными параметрами | — | `doctor --server <несуществующий>`; `scan` с неверным паролем | Понятная причина и подсказка, а не трассировка; учётная запись не заблокирована после одной попытки |

Как сравнивать с известным состоянием: заранее выпишите 3–5 слабых мест стенда
(учётная запись без предварительной аутентификации Kerberos, SPN у администратора,
неограниченное делегирование, пароль `krbtgt` старше года, слабая политика паролей,
правило HBAC «allow all» и т. п.) и отметьте, нашёл ли их инструмент. Затем раскройте
2–3 находки и проверьте, что названные объекты и значения атрибутов существуют.

## 6. Что должно получиться

Папка вывода (`dirauditor-out` по умолчанию, `--out` для другой) после каждого
запуска содержит:

| Файл | Содержимое |
|---|---|
| `snapshot-<метка>.json.zst` | Снимок каталога: собранные объекты и атрибуты, без паролей и хэшей. Содержит имена, DN и SID — обращайтесь как с конфиденциальной информацией |
| `report.html`, `report.json` (в мастере — `report-<метка>.*`) | Отчёт: счётчики, проверки, находки с объектами и атрибутами, объекты нулевого уровня с причиной отнесения, список нечитаемых разделов |
| `run-<метка>.log` | Журнал запуска: версия, аргументы, каждый шаг с меткой времени, примечания, ошибки. Паролей не содержит |

Отчёт считается полным, если в нём есть все четыре части: счётчики, таблица проверок,
объекты нулевого уровня, список «not collected» (пусть и пустой).

Все 68 проверок прототипа — **предварительные**: записи каталога проверок встроены в
программу, не подписаны и ещё не прошли проверку человеком. Отчёт помечает их
`preview`; находку нужно подтвердить по объекту каталога, прежде чем на неё опираться.
Это ожидаемое состояние, а не дефект. Ключ `--no-preview` отключает их — отчёт тогда
содержит только объекты нулевого уровня.

Статусы проверок: `pass` — условие не выполнилось ни на одном объекте; `fail` — есть
находки; `skipped (provider)` — проверка для другой службы каталогов; `skipped (tier)` —
нужен более высокий уровень доступа или запуск на контроллере; `skipped (not-collected)` —
раздел каталога не прочитан; `skipped (quick)` — не входит в быстрое сканирование.

Для ориентира — эталонные стенды, которые проверяются автоматически при каждой сборке:
Samba 4.19 с намеренно ослабленными настройками, обычный пользователь плюс `smb.conf` —
61 объект, 28 проверок с находками, сбор меньше секунды; FreeIPA, `admin` — 355 объектов,
19 проверок с находками. Для доменов в десятки тысяч объектов время и память не
измерялись: зафиксируйте их в отчёте о стенде (строка `snapshot:` и последняя строка
журнала).

## 7. Известные ограничения

- Проверки предварительные (§ 6); проверок DNS и групповых политик нет.
- Если на контроллере нет пригодного сертификата (частый случай у Windows AD и Samba),
  LDAPS и StartTLS не поднимаются. Режим по умолчанию (`--tls auto`) переходит на обычный
  LDAP (389) с шифрованием Kerberos (SASL sealing): пароль превращается в билет Kerberos на
  KDC контроллера, а сессия шифруется и подписывается на открытом сокете. Отдельного действия
  не требуется; как защищено подключение, видно в отчёте и в `run.log`.
- Сборка для Windows до этого раунда вживую не запускалась; живой домен Active Directory
  инструмент ещё не видел. S1 и S2 — самые важные сценарии.
- Проверено на Samba 4.19; на 4.20–4.25 поведение `DSA-0201` и `DSA-0220` может
  отличаться. Эталонный FreeIPA — без DNS и доверительных отношений, поэтому
  `DSA-0116`, `DSA-0118`, `DSA-0119` проверены только на синтетических данных.
- Особенности ALD Pro и РЕД АДМ (собственные схемы, политики, PKI) не учитывались.
- Самоподписанные сертификаты Samba до 4.24.0 часто имеют отрицательный серийный номер;
  программа их принимает. Проверка цепочки и `--pin` при этом работают как обычно.
- Страница мастера доступна только с машины запуска (`127.0.0.1`), удалённого доступа
  нет — так задумано.
- Кода подписи нет, SmartScreen предупреждает (§ 2).

## 8. Что приложить к отчёту об ошибке

Для каждого замечания — issue в репозитории `atsvetko/directory-auditor` (при наличии
доступа) или письмо автору. Приложите:

1. `run-<метка>.log` — обязательно.
2. `report.json` — для замечаний к проверкам и объектам нулевого уровня.
3. Вывод `dirauditor version`, ОС и версию службы каталогов (`samba -V`,
   `ipa --version`, уровень функциональности леса для Active Directory).
4. Для ошибок подключения — вывод `dirauditor doctor --domain … --server …`.
5. Для ложного срабатывания или пропуска — DN объекта, значение атрибута и что ожидали.
6. Снимок `snapshot-*.json.zst` — только если его допустимо передавать: он содержит имена,
   DN и SID объектов. Инструмент обезличивания снимков появится в следующей сборке.

Короткий шаблон: платформа и версия → сценарий (S1–S8) → команда или шаги в мастере →
что ожидали → что получили → вложения.

## 9. Контроль «только чтение»

Программа не содержит кода изменения каталога: при сборке проверяется, что в исполняемый
файл не попали функции LDAP modify, add и delete. Чтобы убедиться на стенде, включите
аудит изменений каталога на время проверки — в Active Directory политику «Аудит изменений
службы каталогов» (событие 5136), в Samba класс журналирования `dsdb_audit` — и
убедитесь, что от учётной записи аудита нет ни одного события изменения. Полный перечень
действий программы: `dirauditor manifest` (сеть, процессы, записи на диск, учётные данные).
